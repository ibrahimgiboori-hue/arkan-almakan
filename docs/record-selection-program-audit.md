# تدقيق الاختيار المتعدد كنطاق عمل في البرنامج

## القاعدة

الاختيار المتعدد ليس عمود Checkbox محليًا. هو `record-set action scope` مركزي: المستخدم يحدد سجلات مستقرة الهوية، ثم يختار إجراءً معلنًا يدعم هذا النطاق. التحديد وحده لا يغير أي بيانات.

- يتصفّر التحديد عند تغيير مجموعة البيانات: شهر، مشروع، فترة، فلتر جذري أو سجل أب.
- «تحديد الكل» يعني السجلات الظاهرة والقابلة للتحديد في السطح الحالي، إلا إذا كان الإجراء يقول بوضوح «كل الكشف».
- الطباعة والتصدير يحترمان المحدد ولا يعودان بصمت إلى التقرير الكامل.
- إنشاء معاملة جماعية يحتاج مصدر Batch/Snapshot خادميًا يتحقق من السجلات والمبالغ ويقفلها حسب الحالة.
- التقارير المشتقة لا تتحول إلى معاملات لمجرد أن المستخدم حدد صفوفًا منها.
- الاعتماد/الرفض/الحذف الجماعي ممنوع افتراضيًا، ولا يفتح إلا بإجراء معلن صراحةً وبقواعد خادم مناسبة.

## التصنيف التشغيلي

### 1. Transaction batch — تحديد ينشئ معاملة مستقلة

**الرواتب**: النموذج المرجعي. دفتر الشهر يبقى وعاءً، والموظفون المحددون فقط يُنسخون إلى `payroll_approval_batch` مع Snapshot للمبالغ. المعاد للتعديل يعاد إرسال نفس الـBatch، ولا تُجر بقية صفوف الشهر إلى المعاملة.

مرشحون لاحقون لنفس النمط فقط بعد تعريف Batch حقيقي: دفعات مصروفات مختارة، دفعات تسويات مقاولين، أو أوامر صرف متعددة. لا يجوز ربطها مباشرة بتحديد واجهة دون سجل معاملة خادمي.

### 2. Operational bulk — إجراء تشغيلي على سجلات متعددة

**الحضور الميداني**: يوجد بالفعل اختيار محلي داخل `BulkAttendanceList`. السلوك صحيح من ناحية الاستخدام (تحديد عدة عمال ثم كامل/نصف)، لكنه يجب أن ينتقل إلى محرك الاختيار المشترك حتى لا يبقى دستورًا محليًا ثانيًا.

**إدخالات الموقع**: `site-operations` يجمع حضورًا ومصروفات ومخرجات تشغيلية وله مفهوم `operation_entry_batches`. يحتاج Adapter من نطاق التحديد المركزي إلى الـBatch الموجود، مع إبقاء كل نوع حركة وقواعده منفصلة وعدم تحويل كل ما على الشاشة إلى عملية واحدة عمياء.

### 3. Report scope — تحديد للطباعة/التصدير والتحليل فقط

**ميزانية التشغيل**: البنود في `budget_period_statement` تقرير/كشف مشتق. يمكن اختيار عدة `line_id` وطباعة المحدد مع إعادة حساب إجمالياته، لكن لا ينشأ «اعتماد ميزانية» من الصفوف المحددة ما لم يُعرّف لاحقًا مصدر معاملة حقيقي.

**سجل الموظفين**: مناسب لـ«طباعة/تصدير المحدد» ومراسلات أو تقارير مجمعة لاحقًا. تغيير حالة أو حذف عدة موظفين لا يُفتح افتراضيًا.

**تقارير التايم شيت**: التقرير الحالي يختار مشروعًا ومقاولًا وفترة ثم يطبع كامل الـRoster. المرشح الصحيح هو اختيار عمال محددين داخل الـRoster لطباعة نسخة محددة، مع بقاء الحضور نفسه في مصدره الأصلي.

**المقاولون/المشاريع/العروض/الأرشيف/المستندات**: تصلح للاختيار من أجل طباعة، تصدير، تنزيل أو إجراءات آمنة معلنة حسب نوع السجل. لا تعني إضافة حذف أو تغيير حالة جماعي تلقائي.

### 4. High-risk decision — لا قرار جماعي افتراضي

**مركز الاعتمادات**: كل معاملة لها نسخة ومسار ومرحلة وملاحظة ووجهة. يمكن مستقبلًا تحديد عدة معاملات للفحص أو التصدير، لكن `اعتماد/رفض/إرجاع` جماعي ممنوع افتراضيًا لأن القرار قد يختلف في الأثر والمرحلة والتبرير.

**الإجازات والانضباط والمعاملات المالية**: السجل قد يكون قابلًا للتحديد للطباعة/التصدير، لكن الإجراء النظامي يبقى لكل معاملة ما لم يوجد عقد Batch صريح يثبت أن القرار الجماعي مشروع ومتجانس.

## ما تم إدخاله في النواة

- `WORK_ACTION_SCOPE.SELECTION` في دستور سطح العمل.
- `WORK_SELECTION_POLICY` يمنع أن يصبح الـCheckbox منطق أعمال محليًا.
- `RawGrid.selection` يملك تحديد الصف، تحديد الظاهر المتاح، حالة المحدد، والصفوف غير القابلة للتحديد.
- `WorkSelectionDock` هو مكان الإجراءات التي تعمل على المجموعة المحددة.
- `ProgramAction` يعرف `selectionCount`, `minSelection` ونطاق الإجراء، ويمنع bulk approve/delete افتراضيًا.
- `record-selection.js` يوحد تحويل IDs إلى نطاق طباعة/تصفية بدل اختراع query logic في كل صفحة.

## ترتيب الترحيل

1. الرواتب + ميزانية التشغيل: مرجعان لنمط Transaction Batch وReport Scope.
2. الحضور الميداني: نقل الاختيار المحلي إلى RawGrid/Selection Kernel دون تغيير قواعد الحضور.
3. تقارير التايم شيت: اختيار عمال للطباعة المحددة.
4. الموظفون والمقاولون والمشاريع والمستندات: طباعة/تصدير المحدد، ثم إضافة إجراءات أخرى فقط عند وجود معنى تشغيلي واضح.
5. المصروفات/التسويات: تصميم Batch خادمي قبل السماح بإرسال المحدد كمعاملة.
6. مركز الاعتمادات والإجازات والانضباط: اختيار للقراءة/التصدير أولًا؛ القرار الجماعي يظل مغلقًا حتى تعريف سياسة صريحة.

## ممنوعات معمارية

- ممنوع صفحة تنشئ Set/checkboxes ثم تبني معنى مختلفًا للاختيار دون إعلان نوع النطاق.
- ممنوع `print all` عند وجود إجراء اسمه «طباعة المحدد».
- ممنوع تمرير IDs من المتصفح وحدها كإثبات مالي؛ الخادم يعيد قراءة السجلات ويأخذ Snapshot.
- ممنوع تحويل View/RPC مشتق إلى source transaction لمجرد أنه ظاهر كصفوف.
- ممنوع bulk approve/delete كميزة عامة.
